# Coding Rules

## Change policy:
- Diagnose first
- Keep fix minimal
- Max 3 files per change
- Follow existing project style
- If a UI pattern changes to fix a class of issues, apply it to all relevant screens, not only the reported example
- On mobile, do not squeeze desktop tables into the viewport
- Use mobile-specific cards/lists for tabular admin data when columns/actions can overflow

## Forbidden:
- large refactoring
- unrelated formatting churn
- new dependencies without reason
