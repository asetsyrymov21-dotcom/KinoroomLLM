# Kinorum — инструкции для агента

## Навигация по проекту

Когда тебе нужно найти конкретный файл (модель, роутер, сервис, схему и т.д.) —
сначала прочитай `PROJECT_MAP.md` в корне проекта. Там есть полная карта с путями и описаниями.

Не читай PROJECT_MAP.md при каждом запросе — только когда нужна навигация по файлам.

## Ошибки и отладка

Когда пользователь сообщает об ошибке или что-то не работает —
сначала прочитай `KNOWN_ISSUES.md`. Возможно, проблема уже решена и там есть готовый ответ.

Когда нужно понять контекст архитектурных изменений или «почему так устроено» —
читай `UPDATES.md`.

Не читай эти файлы при каждом запросе — только когда есть ошибка или непонятен контекст изменений.

## Стиль решений

Не предлагай костыли (временные обходы вроде `ALTER USER`, хардкод, патчи поверх сломанного).
Предлагай только правильное решение — то, которое убирает причину проблемы.
Костыли допустимы только явно, как временная мера для диагностики, и с пометкой что это костыль.
